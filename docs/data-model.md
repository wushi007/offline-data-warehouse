# 数据模型与指标口径

DDL 是表结构的最终依据：`etl/ddl.py`，共 19 张表。

| 层 | 表数 | 粒度与职责 |
|---|---:|---|
| ODS | 1 | 保留事件原貌，按 UTC 日期分区 |
| DWD | 2 | 事实与脏数据；事实键为 user_id/event_time/product_id/event_type |
| DIM | 5 | 商品版本、用户、会话、品类、日期 |
| DWS | 4 | 日期×用户/商品/会话/小时 |
| ADS | 7 | 交易、漏斗、商品榜、会话、分时、留存、RFM |

购买次数指 purchase 事件次数，源数据没有独立订单主键，不能当作真实订单系统的订单数。
GMV 按清洗后的 purchase 价格求和，不包含源数据未提供的数量、退款、优惠及汇率换算。

去重键相同时按其它属性稳定排序选一条；脏数据只记优先级最高原因。数量关系为 ODS = 事实 + 脏数据 + 去重记录。

商品属性来自行为事件，每日取主导组合。SCD2 区间采用 [start, end)，当前版本以 9999-12-31 表示。查询不要使用两端闭合的 BETWEEN：

```sql
SELECT * FROM dim.dim_product_scd2
WHERE product_id = 1004856
  AND DATE '2019-10-20' >= dw_start_date
  AND DATE '2019-10-20' < dw_end_date;
```

缺少观测不等于发生属性变化。全量逻辑将非当前版本截止为最后观测日+1；因此存在观测间隙时不保证区间连续，不应把它描述为完整商品主数据历史。

留存以基准日活跃用户为分母；D+1/D+3/D+7 超出可用数据窗口时为 NULL，而非 0。缺失分区与真实零活动必须在数据质量层区分。

RFM 以购买用户计算，F/M 用均值切分，R 以 30 天为界；当前实现清理旧分区后仅保留一个快照，不是历史快照归档。
