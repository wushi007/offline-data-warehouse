# 热点聚合：加盐的代价

这个实验比较按 product_id 聚合时的原始 groupBy、全量加盐、定向加盐和 AQE REBALANCE。它独立于数仓主链路，不是项目安装前提。

```bash
bash skew_lab/run_all.sh 50000000
```

需要已有 HDFS，路径见 common.py。该命令产生实验数据并覆盖本实验结果文件，不要与其它 Spark 任务并行。

## 已保存结果

历史结果位于 results/skew_bench.json；记录的墙钟耗时如下：

| 方案 | 耗时 |
|---|---:|
| 原始 groupBy | 4.28 秒 |
| 全量加盐 64 桶 | 14.13 秒 |
| 定向加盐 | 8.63 秒 |
| AQE REBALANCE | 5.38 秒 |

在这组数据和配置下，原始 groupBy 最快；额外的采样、分组和 shuffle 没有带来耗时收益。不能将 REBALANCE 描述成总体最优。

## 如何理解热点

原始事件的热点比例不等于 reduce 输入比例。SUM/COUNT 支持 map-side partial aggregate，热点数据可能在进入 shuffle 前已被聚合；不能直接断言几千万条热点记录全进入同一个 reducer。

历史脚本同时记录 all 与 reduce 指标。跨 Stage 混合计算 task max/p50，不能证明某个具体聚合 Stage 倾斜，也不能把不同方案不同 Stage 的比率直接当成治理收益。

全量加盐的理论分组上界不代表实际生成了那个数量的中间记录；需读取实际执行计划和 shuffle 指标。

## 结果边界

本轮整理没有重跑这组大规模实验；原始 JSON 保留为历史材料。若要给出更强结论，需要：

- 保存实际数据行数/分布、运行版本、资源和 executed plan。
- 按 query 与相同职责的 Stage 对齐比较，区分重试和推测执行。
- 重复测量并报告分布，不只取一次最优值。
- 对比各方案逐值结果，而非仅对比结果行数。

当前代码仍主要用于探索，不承担“已经证明热点问题被消除”的展示结论。
